# 13 周我误解过什么（W1-W13 实战期复盘）

> W14 #0 复盘文（蓝图 W14 主题）。口径：每条误解 = 曾经的假设 → 实证证据 → 修正后的认知。
> 不写成绩总结（成绩在演示 PPT 与 portfolio），只写认知修正——这是进阶期最值钱的资产。
> 2026-09-26 成文。

## 1. "chunk-size 是检索质量的旋钮"

- **曾经以为**：调分块粒度能显著改变检索质量。
- **实证**：W13 #1 三轮对照（400/800/1200）Recall@5 均 21/29（72%），失败集合完全相同——
  粒度只切 PDF 年报，而失败集中在 .md 小文件用例（本来就单块）。
- **修正**：参数有没有用取决于瓶颈在哪一段。先定位失败模式，再决定调哪个旋钮；
  旋钮不在瓶颈上，调它只是仪式感。
- 证据：[w13-chunk-size-comparison](../eval/retrieval/w13-chunk-size-comparison.md)（2026-09-17）

## 2. "rerank 是精排银弹"

- **曾经以为**：加 reranker 精排，压线误杀/排错位的案例就能救回来。
- **实证**：W13 #3 on/off 均 27/29（93%），+0pp；39 条逐条对比零翻转——残余失败全是
  召回段零产出/语义近域，不在 rerank 能力半径。
- **修正**：两阶段架构里 rerank 只能重排"召回已捞回"的候选；捞不回来的它救不了。
  系统上限由召回段决定，精排只是分配器。
- 证据：[w13-rerank-eval](../eval/retrieval/w13-rerank-eval.md)（09-17 初版，09-18 返工补逐条数据表）

## 3. "few-shot 示例能提升生成质量"

- **曾经以为**：给几个好示例，输出质量会更稳——业界都这么干。
- **实证**：W8 A/B 对照 10 条，49/60 vs 49/60 打平；两处 ±1 分歧都是标注细节噪声，
  非行为差异。
- **修正**：强约束 prompt + schema 输出就位后，few-shot 的边际收益可以是零。
  "业界都这么做"不构成采用理由，数据裁决才构成。
- 证据：[w8-generation-eval §few-shot A/B](../eval/generation/w8-generation-eval.md)（2026-09-08）

## 4. "MCP fetch 超时是冷启动 TLS 缓存"

- **曾经以为**：W12 首两轮超时是首次连接的握手/缓存冷启动，跑热就好。
- **实证**：W13 验收门④三轮取证——运行中实例连续 3 次协议超时（30s）、独立 stdio 探测
  同一服务 1.6s 正常、清洁重启恢复：是**长驻 MCP stdio 会话失活**（子进程在但协议无响应），
  客户端无重连。
- **修正**：长驻连接会静默死亡；"跑一次通"不等于"一直通"。健康检查/重连是长驻连接的
  标配而非增强（W14 #1 修复项）。
- 证据：[m3-acceptance 门④](../plans/m3/m3-acceptance.md)（2026-09-18）

## 5. "静默兜底是稳健"

- **曾经以为**：解析失败时降级为直接回答，是对用户友好的稳健设计。
- **实证**：W11 显式 ReAct 切换首轮，协议原文被兜底当答案直接发给用户——静默降级是
  故障放大器：故障被吞掉，污染直达终端。
- **修正**：降级必须可见（日志/标记/告警三选一以上），协议解析容差是一等职责。
- 证据：[ADR-0015](../adr/0015-explicit-react-loop.md) +
  [w11-react-loop-regression](../eval/generation/w11-react-loop-regression.md)（2026-09-11）

## 6. "judge 的分是客观的"

- **曾经以为**：LLM-as-a-Judge 锚定 5/5 之后，它的分数可以当客观标尺用。
- **实证**：M3 验收同配置两轮复跑，compound 类均分 5.3/4.7、单条 ±1-2 摆动——类别均分
  ±0.5 是噪声带；冰淇淋案 judge 按旧期望扣分，实为**能力进步跑赢黄金集期望**。
- **修正**：judge 是有噪声的测量仪器——单次分数不可裁决，两轮复跑 + 噪声带才是裁决口径；
  黄金集期望会过期，能力进步了要主动重审期望（changelog 机制，v1.2 首例）。
- 证据：[m3-acceptance 门③](../plans/m3/m3-acceptance.md)（2026-09-18）+
  [golden-set-changelog v1.2](../eval/golden-set-changelog.md)（2026-09-26）

## 7. "MatchText 能直接服务自然语言检索"

- **曾经以为**：Qdrant 全文索引（MatchText）开箱即可做中文关键词召回。
- **实证**：W13 实施期 probe 驱动连撞三坑——multilingual 分词器把数字与中文粘连成单 token
  （"12987流程"永不命中）、纯数字单 token 查询被分词器丢弃、高频词二元组洪泛占满候选网。
- **修正**：向量库的全文检索是分词器行为的艺术；中文+代号混合语料必须 probe 先行，
  "支持全文"≠"支持你的语料"。
- 证据：[w13-hybrid-eval §实施期实证](../eval/retrieval/w13-hybrid-eval.md)（2026-09-17）

## 贯穿七条的一条主线

每一次误解都是"未经验证的工程直觉"，每一次修正都来自同一个小闭环：
**先写死裁决标准 → 跑数据 → 服从数据**。
这个闭环（评估驱动 + 数据裁决）是 13 周真正带走的元能力——进阶期继续靠它吃饭。
