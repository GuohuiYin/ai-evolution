## 注入一：Qdrant 停服（考检索层/外部资源定位）

```bash
# 注入（向量库停服，dense 检索腿全灭）
docker stop qdrant

# 恢复
docker start qdrant
```

预期现象（供你核对，不需要告诉我）：知识问答开始硬拒答或报错；sparse 腿降级空路；
日志出现检索段异常。

## 注入二：DeepSeek 断流（考 failover 识别）

```bash
# 注入（把 DeepSeek API 域名指向本机死端，需 sudo 输一次密码）
sudo sh -c 'echo "127.0.0.1 api.deepseek.com" >> /etc/hosts'

# 恢复（删掉追加的那一行；完成后可执行第二行立即生效验证）
sudo sed -i '' '/^127\.0\.0\.1 api\.deepseek\.com$/d' /etc/hosts
curl -s -o /dev/null -w '%{http_code}' https://api.deepseek.com/  # 能连通即恢复
```

预期现象（供你核对）：主模型调用全部失败 → FailoverChatModel 自动切备模型
（Qwen，走 SiliconFlow），**系统继续作答、用户无感**——这起故障的正确答案不是
「系统挂了」，而是「failover 已触发」（台账 byModel 分面会露出备模型）。
