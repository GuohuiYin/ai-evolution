# 内容审核（Moderation）最小防线论述（W18 #3 下篇）

> 2026-10-11。capability-map 安全域挂账"内容审核 ❌——自有语料风险低，
> 但标准答案应有章节"的结案章。定位：风险面诚实盘点 + 防线分层论述 +
> "现在不做"的正当性论证与触发条件。**非强制实现**（计划口径）。

## 一、概念范围：moderation 不等于红线

| 层 | 管什么 | 本项目现状 |
|---|---|---|
| 业务红线 | 域内合规规则：禁买卖建议/目标价/预测（红线 01-03） | ✅ W7 落地 + 红队基线 + redline 黄金集 7 案常驻监考 |
| 内容审核（moderation） | 通用内容安全：违法/有害/隐私/注入载荷/不当内容——与业务域无关的那层 | ❌ 无独立层（本章论述） |
| 评估巡检 | judge compliance 维 + redline 案复跑 | ✅ 已在 eval 体系内 |

红线是"金融问答不该说什么"，moderation 是"任何 LLM 应用都不该进什么、出什么"。
两者不是包含关系而是两层防线——本章论述的是后者。

## 二、自有语料风险面诚实盘点

**语料侧（风险低，结论维持）**：两家上市公司年报 + 速览，公开披露文档，
无 UGC、无爬取、无用户上传——语料投毒面≈0。

**但"语料风险低"不等于"审核需求为零"**，真实风险面在另外三处：

1. **外部内容入口（最高危）**：W12 落地的 MCP `fetchWebPage` 把**未信任网页内容**
   引入上下文——网页里的"忽略之前的指令"是经典间接注入面。语料干净不代表
   上下文干净。
2. **输出侧漏网**：红线判决的边界形态（"拒答但暗示倾向"——judge compliance 1 分档），
   靠 eval 巡检覆盖 7 案，但线上流量无实时审核。
3. **多轮渐进诱导**：单轮红线全拒不代表多轮不被渗透（"先聊业绩→再聊估值→
   那按这个逻辑该买吗"）——multi-turn redline 案（"那它现在值得买入吗"）
   已是这个面的监考席，但只有 1 案。

## 三、防线分层论述（业界标准答案）

| 层 | 机制 | 单次成本 | 适用时机 |
|---|---|---|---|
| L0 规则层 | 关键词/正则/黑名单（注入特征串、PII 模式） | ≈0 | 任何应用 |
| L1 专用分类器 | moderation 专用模型（Llama Guard / OpenAI omni-moderation 类），输入输出双向 | +1 次小模型调用/请求 | 对外开放、多租户 |
| L2 LLM 审核 | 主模型/裁判模型复核输出 | +1 次大模型调用/请求 | 高危行业（医疗/金融面向公众） |

**设计原则**：防线按**风险面**配，不按**能力清单**配—— moderation 不是
"标准产品都要有"的合规贴纸，是对具体暴露面的响应。本项目当前暴露面：
单租户、可信语料、无 UGC、API Key 鉴权 + 限流已有（W12 #2/#3）——
L1/L2 全量接入是过度工程。

## 四、最小防线结论（现在做什么、不做什么）

**已有即最小防线的三件套**：
1. 输入侧：W7 注入防御 + 红线判决（L0 已有）
2. 输出侧：redline 黄金集 7 案 + judge compliance 维巡检（评估体系内已有）
3. 外部内容：MCP fetch 内容在架构上属未信任输入（W12 ADR-0016 已登记边界）

**明确不做**：L1/L2 审核层不实现（计划口径"非强制实现"）——
正当性：单租户 + 可信语料 + 无公开流量，每请求 +1 次审核调用是纯成本无收益。

**触发条件（任一成立即重启本议题，直接进 L1 选型）**：
- 语料接入 UGC / 用户上传文档
- API 对团队外开放或多租户化
- MCP 外部工具面扩大（fetch 之外的写操作类工具）
- 监管/合规要求落地到本产品

## 五、结论

内容审核从"❌ 无章节"到"论述结案"：风险面盘点诚实（语料低风险成立，
但外部内容入口/输出边界/多轮渗透三面登记在案），最小防线三件套指认完毕，
L1/L2 的触发条件显式化。capability-map 行更新为 ✅（论述结案）+ 触发条件登记。
