# 行业大模型标准配方解剖——以 Hi-Dolphin 为例

> 整理日期:2026-10-31 · 参考笔记,与 agent-engineering-roadmap.md 互相印证
> 核心结论:国内行业大模型的标准配方 = 开源基座 + 行业微调 + 蒸馏降本 + 图谱/RAG 双引擎
> 案例:中远海科 Hi-Dolphin(航运)、度小满轩辕(金融)、律所判例微调(法律)

## 1. 行业化训练(基于基座微调)

不是重新教模型说话,而是给"通才"做"岗位培训",三个递进层次:

| 层次 | 做什么 | Hi-Dolphin 实例 |
|---|---|---|
| 继续预训练(CPT) | 喂行业原文语料,泡在行业里 | 200GB 航运专业语料 |
| 指令微调(SFT) | 喂"问题→标准答案"对 | 40 万航运问答对 |
| 偏好对齐(DPO 等) | 喂"好答案 vs 差答案",学行业口味 | 不确定就说不确定 > 强行回答 |

工程分叉:**全量微调**(改全部参数,语料独家且量大时用,如 Hi-Dolphin)vs **LoRA**(只训练外挂"补丁",原参数冻结;便宜快、可按业务线挂多个;90% 企业场景够用)。

其他案例:度小满轩辕(通用基座 + 金融 CPT + 金融 SFT);某头部律所判例库注入 Qwen2.5,法律咨询准确率 +37%,微调成果作为知识产权写入政府服务合同。

## 2. 知识图谱 vs RAG

知识图谱 = 把知识存成"实体—关系—实体"三元组。建设流程:定义本体(实体/关系类型)→ LLM 批量抽取三元组 → 实体对齐消歧 → 入图数据库 → 持续运营。

| | RAG | 知识图谱 |
|---|---|---|
| 存什么 | 文档切块 + 向量 | 结构化三元组 |
| 怎么查 | 语义像不像 | 关系路径连不连 |
| 擅长 | 开放问答、原文有原话 | 多跳推理、精确事实 |
| 短板 | 跨文档拼不起来 | 建设维护贵、覆盖不全 |

**行业做法:不二选一,合体**。Hi-Dolphin 为"知识图谱 + RAG"双引擎;GraphRAG(微软)先在文档上抽小图谱再检索(参见本目录 graphrag.md)。规律:结构化核心知识走图谱,长尾文档走 RAG。

## 3. 国产开源基座格局与落地成本(2026 年)

主流基座(均商用友好协议,可私有化):DeepSeek-V4/R1(性价比标杆)、Qwen 3.5(尺寸梯度最全)、GLM-5(编程对齐 Claude Opus 4.5)、Kimi K2.5(开源规模最大,长上下文)、MiniMax M2.5(Agent 场景优化)。

| 档位 | 方案 | 成本 |
|---|---|---|
| 个人 | Qwen3-0.6B CPU 直跑 / 7B 量化 + 消费级显卡 | ≈0 |
| 小团队 | RAG + <7B 轻量模型,训练租云 GPU(A10 约 1.8 元/时) | 3~8 万 |
| 标准企业 | LoRA 微调 + RAG + 评估体系 | 5~15 万 |
| 深度定制 | 蒸馏专属小模型 | 1~5 万 |
| 私有化推理 | 4-bit 量化本地常驻 | 月均数千元 |

中等企业 50 万内跑通闭环(数据 15~25% / 模型 30~40% / 算力 20~30% / 人力 10~20%)。落地五阶段:场景梳理与 ROI → 选型 → 数据清洗标注 → 微调+RAG+推理优化 → A/B 迭代。**90% 场景不需要从头训练。**

## 4. 蒸馏(Distillation)

让小模型模仿大模型的输出,把能力从大模型"倒"进小模型:

老师模型(如 R1 671B)→ 对同批问题生成带推理过程的答案 → 学生模型(如 7B)拿老师答案当教材学习 → 获得接近老师的推理能力,推理成本降约 1/50。

两种形式:输出蒸馏(学最终答案与置信度)、推理蒸馏(连思维链一起学,如 DeepSeek R1-Distill 系列)。

Hi-Dolphin 实例:"轻量化蒸馏训练 + 灵活部署,保障数据安全,落地 31 类核心场景"——大模型+行业语料产高质量答案,蒸馏出可私有化部署的小模型。

与微调的关系:蒸馏本质是特殊的 SFT,训练数据由老师模型产出而非人工标注,故成本极低(1~5 万档)。
