# Agent 工程化落地路线图（六阶段）· 附本项目实现锚点

> 整理日期:2026-10-29 · 参考性质,不替代周计划与课程地图
> 结构:每阶段 = 目标 / 关键动作 / 业界标准做法 / 过关标准 / **本项目锚点**
> 人话版结论:把"能聊的 Demo"变成"能上线的系统"是六道关,记忆在第五关——
> 它被轻视不是因为不重要,而是多数团队走不到它。

## 阶段 0:场景定义与边界

- **目标**:想清楚做什么、不做什么、怎么算成功
- **关键动作**:定义用户与任务;列能力清单与红线清单;定成功指标(准确率/时延/成本底线)
- **业界做法**:能力域对账——对照标准能力清单(上下文、多轮、记忆、规划、工具、评估、安全、可观测)逐项问"我有吗?没有是有意放弃还是盲区";没有证据 ≠ 没有问题
- **过关标准**:边界成文,评审通过
- **本项目锚点**:`AGENTS.md` §0 质量标准与 §5 金融域三条红线;`docs/capability-map.md`(A14/A15 双参照系差距扫描);`docs/plans/course-map.md`

## 阶段 1:Prompt 工程与单轮基线

- **目标**:不加任何工程手段,先量出模型裸能力,作为后续一切优化的对照组
- **关键动作**:system prompt 初版;30~60 道黄金题;裸模型首跑;失败案例分类(知识缺失/理解错误/格式问题)
- **业界做法**:每项后续优化(检索、改写、精排)的收益都与裸基线对比,否则说不清工程贡献
- **过关标准**:基线分数落档;失败分类完成
- **本项目锚点**:`prompt` 域 + `resources/prompts/*.md`(A13 纪律门:改动必附 eval 跑批);`eval/GoldenCase.java`、`eval/GenerationCase.java`;ADR-0007(eval 门禁机制)

## 阶段 2:上下文与检索管线(RAG)

- **目标**:让模型"有资料可查"
- **关键动作**:切块 → 向量化 → 混合检索(语义向量+关键词两路)→ RRF 融合 → 精排 → 上下文组装;加固件:查询改写、指代消解、零召回防线、检索多样性配额
- **业界做法**:混合检索 + RRF + reranker 是标准答案;每加一个零件就跑检索评估(Recall@K/MRR),只留涨分的
- **过关标准**:召回率超阈值;每条优化有数据背书
- **本项目锚点**:`rag` 域全链:`KnowledgeBaseIngestor`(摄取)/ `Bm25Encoder` + `QdrantSparseRecall`(稀疏路)/ `RrfFuser`(融合)/ `SiliconFlowRerankerClient`(精排)/ `DeepSeekQueryRewriter`(改写)/ `RetrievalDiversityGuard`(多样性配额)/ `RetrievalTraceAspect`(检索观测);ADR-0017(两段式检索设计)、ADR-0012(增量摄取 manifest)、ADR-0006(手工编排);架构图 `docs/arch/diagrams/c4-3-component-rag.md`

## 阶段 3:工具与多步循环(从问答到 Agent)

- **目标**:让模型"能动手做事"
- **关键动作**:工具白名单派发 + 参数校验 + 审计;显式"想—做—看"循环;步数上限优雅退出;长任务持久化编排;高风险动作人工审批(HITL)
- **业界做法**:显式循环优于框架黑盒——轨迹可见、步数可控;长任务用持久化工作流(Temporal)承载崩溃恢复
- **过关标准**:多步任务成功率/平均步数/冗余调用率达标,轨迹可回放
- **本项目锚点**:`loop` 域:`ResearchLoop`/`ResearchLoopEngine`(显式循环)/ `ReactProtocolParser`(文本协议)/ `ToolRegistry` + `ToolExecutor`(白名单派发)/ `LoopListener`(观测端口)/ `loop/temporal/`(持久化编排)/ `loop/pipeline/`(Planner/Builder/Reviewer);`tool` 域 `ToolAuditAspect`(审计切面);`mcp` 域(MCP 双向接入);ADR-0015(显式 ReAct)、ADR-0019(Temporal 可观测)、ADR-0008(工具审计)、ADR-0009(MCP 暴露)、ADR-0016(MCP 白名单);参考 `docs/notes/temporal-minimal-loop.md`

## 阶段 4:评估体系固化(从抽检到门禁)

- **目标**:任何优化以评估数据作为启用门槛
- **关键动作**:检索/生成双轨评估;LLM 当裁判 + 双盲校准;评估入 CI 自动回归;线上流量抽样回流黄金集
- **业界做法**:裁判模型与被测模型隔离;双盲 + 随机换位防位置偏置;评估贯穿全程而非一次性动作
- **过关标准**:回归自动化;裁判一致率校准达标
- **本项目锚点**:`eval` 域:`RetrievalEvaluator`/`GenerationEvaluator`(双轨)/ `LlmEvalJudge`(裁判)/ `EvalGate`(门禁)/ 两个 `*EvalRunner`(跑批);ADR-0014(裁判隔离)、ADR-0007;双盲校准实证:一致率 36.7%→83.3%

## 阶段 5:记忆与个性化(最易被跳过的一关)

- **目标**:跨会话记住用户,从"工具"变"助手"
- **关键动作**:记忆读写分离(后台异步抽取事实、每轮限量注入);事实冲突消解;用户可见可删;记忆质量进评估
- **业界做法**:向量记忆起步、schema 预留事实结构;注入有 token 预算防记忆污染;错误记忆视为质量事故
- **过关标准**:跨会话事实召回正确率达标;错误记忆可被评估发现
- **本项目锚点**:**当前空白**——设计已定稿于 ADR-0021(记忆策略:Qdrant 复用 + 事实结构预留 + 读写分离 + 治理红线);会话内记忆先例见 ADR-0015 决策 5(手工读写窗口历史);能力缺口登记于 `docs/capability-map.md`

## 阶段 6:生产化与运营

- **目标**:可观测、控成本、保安全、能灰度、可回滚
- **关键动作**:全链路追踪(OTel 埋点 + LLM 观测平台);token 级成本账 + 大小模型路由;鉴权限流、提示注入防护、拒答话术单点化;金丝雀发布与回滚
- **业界做法**:采集端锁定 OTel 标准、后端可替换(Phoenix/Langfuse);成本用级联策略(小模型先答);上线金丝雀放量
- **过关标准**:异常可从指标→链路→日志三级下钻;单请求成本可知可控
- **本项目锚点**:`feedback` 域(用户反馈回流)/ `infra` 域(横切设施)/ `compliance` 域(`Disclaimers` 红线文案单点,A12);A6 Micrometer 埋点与 token 计量;ADR-0020(OTel + Phoenix 观测选型)、ADR-0011(红线只告警)、ADR-0005(模型选型)、ADR-0010(统一路由)、ADR-0002(Jib 镜像)与 `k8s/` 清单;选型分析 `docs/notes/llm-observability-phoenix-vs-langfuse.md`

## 贯穿全程的两条横切纪律

1. **eval 驱动**:从黄金题开始,每阶段成功率由同一套考试系统度量——工程化与"调参玄学"的分水岭
2. **决策留痕**:每个选型记录 why / why-not / 重评触发条件(ADR 机制,业界称 design doc / RFC)
