# P0 Prompt 改前/改后效果对比（L1 退出信号实证）

> 日期：2026-09-04 · 模型：DeepSeek（deepseek-chat）· 数据：MockStockDataClient 种子数据
> 对照：v0 = zero-shot 裸指令基线；v1 = CO-STAR 六要素 + few-shot
> 原始样本：[p0-samples/](p0-samples/)（5 份 JSON，含一次稳定性复跑）

## 实验设计

同一输入（600519 贵州茅台 / 300750 宁德时代，mock 行情+财务数据），分别经 `POST /ai/analyze` 以 v0/v1 两个 prompt 版本调用真实模型；600519-v1 额外复跑一次观察非确定性。

评估维度：① 数据锚定（陈述是否全部来自给定数据）② 结构化完整率 ③ 来源引用完整性 ④ 解析稳定性。

## 实测记录与判读

### 维度一：数据锚定（幻觉控制）——v1 胜 ✅

| 版本 | 实测输出摘录（风险点字段） | 判读 |
|---|---|---|
| v0 茅台 | "高估值和机构持仓集中可能带来调整风险"、"可能受年末市场情绪或资金流动影响"、"历史长期表现持续向好" | 输入数据只有一年财务 + 两天行情——"高估值""机构持仓""长期向好"**全是数据外编造** |
| v1 茅台 | "仅单一会计年度财务数据，营收及利润趋势判断数据不足"、"行情数据仅覆盖两个交易日，价格波动趋势判断数据不足" | 无一条数据外判断；风险点全部是对数据边界的诚实标注 |

**结论**：v1 的 Tone 约束（"数据未覆盖的方面明确写'数据不足'"）被模型忠实执行——few-shot 示例里的
`"仅单一会计年度数据，趋势判断数据不足"` 句式被直接迁移。few-shot 对内容保真度的价值有实证。

### 维度二：结构化完整率——打平（100% vs 100%，当解析成功时）

**结论：输出格式是代码层（`.entity()` schema 强制）保证的，不是 prompt 工程保证的。**
Prompt 工程的真正价值在**内容保真度**——这是本次实验最重要的认知收获。

### 维度三：来源引用颗粒度——v1 胜 ✅

| 版本 | 实测 sources 字段 |
|---|---|
| v0 茅台 | `["mock数据（时点: 2025-04-30）"]` —— 笼统一条 |
| v1 茅台 | `["mock，时点: 2025-04-30（财务数据）", "mock，时点: 2025-04-30（行情数据）"]` —— 逐条分列 |

**判读**：红线 03（来源与时点）在输出端的颗粒度提升，v1 逐条化。

### 维度四：解析稳定性——v1 暴露结构化输出的固有脆弱性 ⚠️

| 组合 | 成功/尝试 | 备注 |
|---|---|---|
| 600519-v0 | 2/2 | 裸指令反而稳定 |
| 300750-v0 | 1/1 | |
| 300750-v1 | 1/1 | |
| 600519-v1 | 3/7 | 4 次模型输出非法 JSON，`.entity()` 解析失败 |

**判读**：假设是 v1 prompt 更长（CO-STAR + 示例）且茅台数据行更多 → 长输出更易产生非法 JSON。
**这不是 v1 的"退步"，而是揭示了一个生产真相：结构化输出必须有 Correct 机制兜底。**
已完成的兜底：解析失败从 500 修正为语义正确的 502（`upstream_output_parse_error`，A7 契约对齐）。
待办：解析失败重试一次 + 修复提示词（"上次输出不合法，请严格输出 JSON"）——Harness Correct 层的第一个真实需求。

### 维度五：非确定性观察（稳定性复跑）

| 实测（600519-v1 两次成功输出） | 判读 |
|---|---|
| "净利率约 49.51%" vs "约 49.5%"，结构与事实完全一致 | 非确定性存在于**措辞层**，事实层稳定——eval 断言应针对事实与结构，不断言逐字文本 |

## L1 退出信号结论

- 场景基线确立：v1 在数据锚定、来源颗粒度、数据不足标注三个维度全面优于 v0（有实测）
- 优化收益递减判断依据已具备：下一步优化的边际收益已不在 prompt 措辞，而在 Harness（Correct 重试）——**这正是"该离开 L1 进入 L3"的信号本身**

## 附：方法论备注

- few-shot 示例使用虚构公司 000001，与评估集、真实股票代码完全隔离（防泄漏）
- 本次为人工评审（5 样本）；LLM-as-a-Judge 自动化评分在 W8 落地
