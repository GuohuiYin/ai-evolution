## 判读（Owner 守线：降幅 ≥40% 值得 / <20% 止步；质量跌落 ≤ 抖动带 ±0.2）

- Token 降幅 **9.7%**（W22 初测 2.0%）→ 仍 <20%，**登记认知止步**

## 归因分离（本次重测的第二使命：库太小 vs 注入点仅覆盖 Agent 通路）

两个假设的分离结论：

1. **「库太小」假设成立且可量化**：技能 1→4 个，降幅 2.0%→9.7%（约 5 倍），
   触发案 3→20 案（覆盖率 5%→35%）。降幅随库规模近似线性放大，扩列有效。
2. **结构性上限仍在**：a) 注入点只挂 Agent 循环，RAG 通路案（多数未触发案）两臂
   prompt 完全同构，颗粒无收；b) 触发案内部降幅 11.0%——省去的是未命中技能正文
   （约 1.7k tokens/案），而 prompt 大头是检索原文与多轮历史，比重难撼动。

## 结论（按预设守线）

降幅 9.7% < 20% → **继续登记认知，机制止步不硬上**：`ai.skill.mode` 默认保持 off，
机制代码与 4 个 skill 保留在库（测试覆盖，零运行时影响）。重启条件修订：
技能库扩列至 ≥8 个，或 RAG 通路接入注入点（diversity 守卫之后检索链已有
可挂点，接入需先评估注入内容对措辞边界的影响）时，重跑本测量。
