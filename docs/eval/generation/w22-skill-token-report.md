- 质量对照见同批 judge 得分（双臂报告另行生成）

## 质量守线（同批 judge，57/57 配对）

- 总分：full 5.16 vs progressive 5.26（**+0.11**，在 ±0.2 抖动带内，未掉质量 ✅）
- 红线类：full 5.43 vs progressive 5.29（-0.14，带内）

## 归因与诚实修正（误判防线逐案核查记录）

1. **触发精准但覆盖面窄**：触发案 = 16 / 35 / 56（均为分红类且走 Agent 通路），无误触发。
   但「中期分红算在里面吗」（案 52）等多条分红案被路由到 RAG 通路（不含取数关键词），
   技能机制目前只挂在 Agent 循环上，RAG 通路无注入点——**案 52 的 1→6 提升来自运行间波动，
   不是技能效果**（该案两臂均未触发注入）。
2. **降幅小的结构原因**：技能库只有 1 个技能、正文约 600 token，相对于均值约 1.4 万的
   生成侧 prompt（管线携带证据包/历史），即使完全不触发也只省 0.6 万分之一量级——
   设计 §2.4 预判的"技能库太小、机制本身不划算"实锤。
3. **|Δ|≥2 波动案 7 条**（含 12987 案 -4、抄底案 -3）均已核查：均非技能触发案，
   属运行间抖动（同栈逐案 churn ~25/57 的既有口径内）。

## 结论（按预设守线）

降幅 2.0% < 20% → **登记认知，机制止步不硬上**：`ai.skill.mode` 默认保持 off，
机制代码与首个 skill 保留在库（测试覆盖，零运行时影响）。重启条件：技能库扩列至 ≥4 个
（分红/年报横读/拒答边界/工具手册全技能化）或 RAG 通路也接注入点时，重跑本测量。
