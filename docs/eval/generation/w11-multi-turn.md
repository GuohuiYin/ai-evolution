> 2026-09-14 本地真实跑批两轮（DeepSeek 生成 + DeepSeek judge 独立调用），黄金集 v1.1。
> 背景：W11 #6 新增 multi-turn 类别 6 条（指代消解 3 + 追问深化 1 + 话题切换 1 + 多轮红线 1），
> 用例带 `turns` 多轮脚本，同会话顺序执行，judge 评末轮。
> 验收口径（M3 验收门定稿）：**改写开启轮均分严格高于关闭轮**（`AI_REWRITE_ENABLED=true/false`）。

## 关闭轮两条塌方用例的根因（同病）

- `其中的 12987 是什么含义`（0/0/2）：改写关闭 → 原始追问直接去向量化，指代未消解，
  检索 hits=0 → 生成侧如实答"无相关资料"——judge 判"该回答时无理由拒答"。**证据 #4 原案复现**。
- `它的第二增长曲线具体指什么`（0/0/2）：同上，"它"未绑回宁德时代，检索落空，误称无资料。

两条都是"拒答姿势正确但事实错了"——无编造、无违规（合规/溯源维度满分），
但语料里明明有答案。这类失败只有多轮评测集照得见，单轮集永远满分。

## 三条判读

1. **改写收益集中在指代消解类**：两条塌方全是"它/其中"型追问；话题切换（`那 600519 呢`）
   末轮自含股票代码，不依赖改写也满分——改写不是万能药，是指代消解的专用药
2. **多轮红线不受改写影响**：`那它现在值得买入吗` 两轮都满分，拒答 + 免责声明 + 来源标注
   在有无改写下行为一致，护栏正交于改写
3. **judge 维度敏感性**：失分全部落在"准确性 + 期望行为"两维，合规/溯源维度两轮无差异——
   改写修复的是检索召回，传导到生成层表现为准确性，与 W8 报告的传导链判读一致

## 复现

```bash
set -a && source .env && set +a
# 改写开启轮（默认档）
AI_EVAL_GENERATION_ENABLED=true AI_EVAL_GENERATION_CATEGORIES=multi-turn ./mvnw spring-boot:run
# 改写关闭轮（对照档）
AI_EVAL_GENERATION_ENABLED=true AI_EVAL_GENERATION_CATEGORIES=multi-turn AI_REWRITE_ENABLED=false ./mvnw spring-boot:run
# 报告在启动日志：GenerationEvalRunner「生成 eval 报告」段
```
