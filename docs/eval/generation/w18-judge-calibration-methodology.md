# W18 Judge 校准测量 · 方法论（#1 先行项）

> 2026-10-10 立。目的：给蓝图验收口径"Judge 与人工抽检一致率 ≥80%"第一次补上测量证据。
> Judge 现状只有"锚定 5/5"的一次性校准（W8），无持续一致率证据。
> 本文是**方法论成文**（计划 #1 验收条件之二），测量执行与一致率报告另落
> `w18-judge-calibration.md`。Owner 裁决记录：22 条全量人工打分，不抽样。

## 一、测量对象

生成黄金集 v1.2 全量 **22 条**（`eval/golden-set-generation.json`）：

| 类别 | 条数 | 打分要点 |
|---|---|---|
| redline | 3 | compliance 维为主战场（拒答质量） |
| in-domain-unanswerable | 4 | 拒答/答缺口两类期望并存（冰淇淋案 answer-with-gap） |
| factual | 6 | accuracy + grounding 并重 |
| compound | 3 | 两部分都要答，遗漏即扣分 |
| multi-turn | 6 | 上下文指代/切换正确性计入 accuracy |

三维 rubric 与 judge 完全一致（[eval-judge-v1.md](../../../src/main/resources/prompts/eval-judge-v1.md)
原文：accuracy / compliance / grounding 各 0/1/2）——**人工用同一把尺，一致率才有意义**。

## 二、流程（五步）

1. **跑批取答案**：`AI_EVAL_GENERATION_ENABLED=true ./mvnw spring-boot:run`，线上默认配置
   全量 22 条；完整日志落盘存档（`docs/eval/generation/logs/w18-calibration-run.log`），
   内含每案回答 + judge 三维分 + reason。此为**唯一含 judge 分数的工件**。
2. **工作表生成**：22 案乱序（固定种子 `20261011`，脚本生成，顺序记录可复跑）；
   每案展示：问题 / 期望行为 / 参照答案 / 被测回答 / 打分格。
   **双盲红线：工作表不含任何 judge 分数与 reason。**
3. **人工打分**：Owner 一人全量打分（**2026-10-11 口径变更：暂无协作者，降为单评分人**），
   打分期间禁止查看跑批日志。每格 0/1/2 + 可选一行扣分备注。
4. **成对对比（辅助信号）**：每案末尾附【甲 / 乙】——被测回答与参照答案原文随机左右
   （同种子另一路随机），评者选"甲更好 / 乙更好 / 相当"。用途：交叉验证 accuracy 维
   （judge 给 2 分但人工判参照明显更好 → 不一致线索，归入归因）。
   已知局限：参照答案是要点式、被测回答是成文，体裁不对称；且打分阶段两段文本均已出现，
   评者可能认出甲乙身份（半盲）——故甲乙不标身份、位置随机，结论仅作线索不作判据。
5. **一致率计算 + 归因**：揭盲后逐格比对，不一致案逐条归因
   （judge prompt 偏差 / 期望工程问题 / 人工失误），落报告。

## 三、一致率口径（本次定稿）

- **主口径 · 逐格 exact-match 率**：3 维 × 22 案 = 66 格，
  报 Owner↔Judge 一致率；**达标线 ≥80%**（蓝图口径）。
- **参照系 · 人际一致率（挂账）**：暂无协作者，本轮不测——失去"judge 是否比人还不像人"
  的判据，报告披露此降级；日后找到第二评分人可用同批工作表（种子可复跑）补测。
- **辅口径 · ±1 容差率**：评分粒度粗（0/1/2）的稳健性检查，只披露不考核。
- **不达标处置**：judge prompt 修订后复测（同批回答重判，不重跑生成），
  修订点与复测结果入报告。

## 四、双盲纪律（三条）

1. 工作表生成脚本只取日志中的 query/期望/参照/回答四字段，分数与 reason 不落地。
2. Owner 打分完成前，任何人（含我）不在对话中披露逐案 judge 分数。
3. 打分表回收后才做一致率计算——先收卷、后比对，防中途对答案。
