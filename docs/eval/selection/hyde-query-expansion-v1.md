# HyDE / 查询扩展评估报告 v1（调研论证型）

> 时点：2026-09-14（W11 #8）· 性质：调研论证，非实测（计划明确要求不动代码）
> 结论依据：2024-2026 公开证据 + 本项目 W11 实测病灶数据
> 核心判断：**HyDE 解的病（查询-文档词汇鸿沟）不是本项目实测的病（指代消解）**——
> 裁决：现阶段不采纳，重评触发条件在案

## 1. 评估对象

- **HyDE**（Hypothetical Document Embeddings, arXiv 2212.10496）：LLM 先生成一段"假设答案"，
  向量化这段答案而非原始查询去做检索，桥接查询与文档的词汇/语体鸿沟
- **查询扩展**（multi-query / RAG-Fusion 同族）：多次生成多角度改写，多路召回后融合（RRF）
- 两者同属"查询侧变换"，成本结构相同（每查询多 1~N 次生成调用），一并裁决

## 2. 本项目实测背景（裁决的锚）

| 证据 | 内容 |
|---|---|
| 证据 #4（W10 冒烟） | 追问"其中的 12987 是什么含义"检索 hits=0——病灶是**指代未消解**，不是词汇鸿沟 |
| W11 #5/#6 | 查询改写落地，多轮 eval 改写开 6.0/6 vs 关 4.5/6——指代消解已被改写**解决且量化** |
| W8 检索基线 | Recall@5 72%，失分聚在 paraphrase/literal/adversarial——W13 混合检索 + rerank 已排期对症 |
| W8 成本账 | 单次问答 ¥0.0054 敏感区；SSE 流式体验是产品形态 |

## 3. 不采纳理由（按权重排序）

1. **病灶错位**：实测塌方（12987 / 第二增长曲线两条 2/6）全是指代未消解 → hits=0 → 误拒答，
   已由改写修复；HyDE 对"它/其中"型追问同样无解（假设文档生成照样不知道"它"是谁）
2. **适用边界排除**：本域查询多含强标识符（600519 / 12987 / 归母净利润），
   业界指南明确"查询已含强关键词/标识符时避免 HyDE"；且金融域对幻觉敏感——
   假设文档编错数字会把检索向量带偏（检索探针污染），与本项目溯源红线相冲
3. **收益被更便宜的解法覆盖**：词汇鸿沟的对症解法是混合检索（BM25 稀疏路直接命中
   字面信号）+ rerank，W13 已排期；2026 年证据：成熟嵌入（bge-m3 同级）+ 混合基线上，
   HyDE 增量收益小到"只有按查询难度门控才划算"
4. **成本/延迟实打实**：每查询多一次生成调用，公开实测 +43~60% 延迟量级；
   与流式体验、成本账、以及"先正确后快"的本周纪律都不兼容

## 4. 重评触发条件（任一成立即重评，且按 HyDE-on-uncertainty 门控模式而非全开）

1. W13 混合检索 + rerank 落地后，检索黄金集 paraphrase 类失分仍聚集
2. 语料规模上到万级，或文体差异显著变大（当前全是研报/年报同构文体）
3. 混合检索后 Recall@5 仍 < 80%（W11 #4 定稿的混合检索启用阈值线）
