# 引用忠实度强化论述（W18 #3 上篇）

> 2026-10-11。capability-map 检索管线行挂账"引用忠实度 ⚠️ 生成 eval 溯源维部分覆盖"的结案章。
> 定位：讲清"引用忠实度"这个评估维度的度量现状、与业界标准答案的差距、防线设计——
> 本章是论述不是施工令，落地项以候选形式进 W19+ 裁决。

## 一、概念澄清：三个常被混为一谈的东西

| 概念 | 测什么 | 本项目现状 |
|---|---|---|
| **溯源标注率**（grounding） | 答案里的数字/事实标没标来源与时点 | ✅ judge grounding 维（0/1/2），W18 #1 校准 95.5% 达标 |
| **引用忠实度**（citation fidelity） | 标的来源**对不对**——答案声称的出处是否真实支撑该陈述 | ⚠️ 未直接测量（本章主题） |
| **结构化来源一致性** | 答案文本自述来源与响应 `sources` 字段是否一致 | ❌ 从未校验 |

业界标准答案的锚点：AIS（Attributable to Identified Sources，Rashkin 2022）把
"可归因"定义为——来源足以让评审者推出该陈述；ALCE（Gao 2023）进一步把它量化成
citation precision（引的每篇都支撑）× recall（该引的都引了）。RAGAS 的 faithfulness
只测"答案是否被检索上下文支撑"，不测"标注给用户的来源对不对"——**标注诚实性与
上下文忠实性是两回事**，我们的 EPS 60.79 案就是前者塌方后者无恙的实证。

## 二、现状管线解剖（代码锚）

```
检索 → 生成（prompt 要求标注来源+时点）→ 响应（reply + sources: List<SourceDocument>）
           ↑ 文本内自述来源                    ↑ 结构化来源列表
           judge grounding 维测这层           这层从未进过任何评估
```

- `ChatResponse.sources`（[ChatResponse.java](../../src/main/java/com/aievolution/chat/ChatResponse.java)）
  是检索侧命中文档的结构化回传——它描述"生成时看到了什么"，不描述"答案每一句来自哪里"
- judge grounding 维测的是文本自述标注的完整性（缺文件/缺时点扣分），
  **但 judge 不核对自述来源与 sources 字段的一致性**——答案写"年报 p5"而 sources
  里根本没有年报，当前体系抓不到
- 黄金集侧的 Related 监考席已就位：F5（营业总收入 vs 营业收入口径）、F7（行业 vs 公司归属）、
  M7（分红口径归属）、C1/M1（EPS 60.79 波动面）——口径与归属区分案是引用忠实度的
  前端哨兵，W18 #2 已落地

## 三、防线设计（分层论述）

| 层 | 机制 | 成本 | 现状/处置 |
|---|---|---|---|
| L0 生成约束 | prompt 强制"来源文件+时点"双要素 + 红线 03 来源诚实标注（mock 也须标工具名） | 零边际 | ✅ 已有（W18 C-lite 口径已对齐工具来源） |
| L1 结构化一致性校验 | **程序化**校验：答案文本提及的来源文件名 ∩ `sources` 字段；交集为空则告警/降级 | 零模型调用，纯字符串比对 | 🔵 **候选 W19+**——性价比最高的下一刀 |
| L2 judge 评估维 | grounding 维现有 rubric + 校准机制（W18 #1 方法论可复跑） | 每案 1 次 judge 调用 | ✅ 已有且校准达标 |
| L3 逐句归因 | sentence-level attribution（每句挂 chunk id，ALCE 式 precision/recall） | 高（需生成协议改造 + 归因模型） | ⛔ 现阶段明确不做——语料 3 文件规模下投入产出倒挂，语料上百 chunk 后重评 |

**设计原则**：引用忠实度的防线优先用**程序化校验**（L1）而非更多 LLM 评估（L3）——
能用确定性代码抓住的不一致，不该再花一次模型调用去"猜"。这与 W16 BM25 裁决的
净交换比思维同源：每一层防线都要回答"它抓到的错，上一层为什么抓不住"。

## 四、与既有机制的联动

1. **轮换机制首演**（W18 #4 已定稿）：2025/2026 新报入库后，口径案（F5/F7 族）
   是最敏感的监考席——新语料的引用忠实度复跑应进首演验收清单
2. **人工反馈回路**（capability-map 挂起项）：👍/👎 badcase 回流时，
   引用错误类 badcase 应优先入黄金集（EPS 60.79 这种顽固面正是人工反馈最该补的）
3. **judge 校准复测**：若 L1 落地，校准方法论（W18 #1）可直接复用于
   "程序化校验与人工判定的一致率"——方法论资产复用，零新增设计成本

## 五、结论

引用忠实度从"⚠️ 部分覆盖"到"论述完整"：缺口被精确定义为**引用对不对**（而非标没标），
防线分层成型（L0/L2 已有，L1 候选 W19+，L3 明确不做），度量与轮换/反馈回路挂钩。
本capability-map 行更新为 ✅（论述结案）+ L1 候选登记。
