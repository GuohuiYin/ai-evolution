## 三、意外收获（首演超产出部分）

1. **"参照推翻"条款首次启用（F4 法定代表人真值反转）**：2024 年报=张德芹、
   2025 年报 p5 与 2026 半年报 p4/p110=陈华（pypdf 三份取证）。模型答"陈华"正确，
   judge 拿过期参照判 0/0/0 并称"编造来源"。参照已重锚定（Owner 裁决①）——
   轮换纪律为"黄金集自身时效"设计的保险丝，第一次真实熔断，证明条款不是空文。
2. **judge 校准证据时效破产（36.7%，11/30 不达标）**：W18 缺陷低频期建立的 95.5%
   校准证据未通过缺陷爆发期复测——judge 对 Thought 泄漏 preamble 系统性偏松
   （5 案同向），且自身前后不一致（W18 五粮液泄漏 0/0/0 vs 本轮同类满分）。
   **方法论教训：校准证据与语料/缺陷状态绑定，轮换或缺陷状态变化后必须复测。**
3. **速览召回挤压族显形（检索↔生成跨侧同因）**：语料 3→8 源后年报 chunk 密度上升，
   速览锚点被挤出有效视野——检索侧 12987（❌✅❌）/取酒轮次（✅❌✅）擦边抖动，
   生成侧 M3 第二增长曲线、CP 赤水河约束遗漏、G1 错误拒答同族。这是轮换的
   结构效应而非缺陷，裁决候选：速览 chunk 加权或 docType 过滤实验（W20+）。
4. **Thought 泄漏双机制拆解（#3 收官追加取证，本轮新结论）**：
   - **机制一·真泄漏（用户可见）**：协议违背降级——模型写中文"思考："替代"Thought:"，
     `ReactProtocolParser` 匹配失败返回 empty，`DeepSeekResearchModel` 兜底
     `new ModelTurn.Final("", raw)` 把原文当答案。六批日志共 7 次
     `protocol violation` WARN，全部以"思考："开场。
   - **机制二·评测假象（用户不可见）**：MAX_STEPS 触顶（6 步）——F3 分红案实锤
     （日志行 19135 进案→21442 `exit stopReason=MAX_STEPS steps=6`）。系统真实
     返回的是优雅降级文案，但该文案非 API `text` 字段，工作表提取脚本取区域内
     最后一条 `text` 行捞到 ReAct 中间步，判读为"泄漏"。v3 基线机制①的表述
     以此拆解为准：6 个泄漏表象案是真泄漏与提取假象的混合，修复提取脚本后
     重新归类。
   - W18 罕见、W19 爆发的原因：跨年口径并存（40.21% 末期 vs 42.56% 含中期）
     驱动模型"换关键词再检索"，平均步数拉长→触顶与长输出格式漂移概率双升；
     mock 工具不支持 2025/2026 查询进一步烧步数。**非能力回归。**
5. **eval 基建事故证据链**：DeepSeek PrematureCloseException ×2、Qdrant Exited 143 ×2，
   分批跑+探活处置有效。runner 逐案增量输出、Qdrant restart policy/Compose 托管、
   API 断连指数退避重试三项改进全部有现场证据，维持 W19+ 候选。
