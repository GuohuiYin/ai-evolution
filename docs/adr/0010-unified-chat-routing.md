# ADR-0010：对话统一入口 + 规则路由（/ai/chat 单入口，/ai/agent 保留为显式旁路）

- 状态：已接受
- 日期：2026-09-07（W5 遗留裁决项"对话接口不对称"，W6 落地）

## 背景

两条对话通路能力不对等：`/ai/chat`（RAG 固定管道，有硬拒答与结构化 sources，但无工具）、`/ai/agent`（三工具调度，但 sources 恒空）。对话页只接 `/ai/chat`，用户问"营收+工艺"复合问题时拿不到工具能力，体验落差实证于 2026-09-07 联调。W5 遗留裁决：是否统一路由。

## 决策

1. **单入口**：`/ai/chat` 对外唯一对话入口，实际实现为 `RoutingChatService`（`@Primary` 注入 `ChatService` 接口），路由决策内聚于 `ChatRouter`。
2. **规则路由（非模型路由）**：含 6 位股票代码或取数关键词（`ai.chat.agent-keywords` 外置配置，A11）→ AGENT；其余 → RAG。选规则而非模型裁决的理由：确定性、零延迟、零成本、可单测；路由错误代价不对称——误入 AGENT 不致命（工具是超集能力，仍能检索作答），误入 RAG 才丢能力，故规则宁可偏 AGENT。
3. **`/ai/agent` 保留**为显式工具入口（测试/调试旁路），OpenAPI 标注其定位。

## 备选方案

- 模型自行路由（LLM classifier）：引入延迟/成本/不确定性，现阶段过度设计。否决。

## 演化方向（路由的三个层次，勿混淆）

本 ADR 裁决的是**通道路由**（"走哪条能力链路"）。路由在架构上还有另外两个正交维度，明确区分以免概念混淆：

1. **通道路由的实现演化**：规则（现状）→ "规则兜高频 + 模型分类器接管长尾"（意图空间复杂到规则写不动时启用）。路由决策已内聚于 `ChatRouter`，换实现上层无感。
2. **大小模型路由（model-tier routing / LLM cascading）**：正交的第二层——通路内部"用哪个模型回答"。生产流量 70%+ 的问题小模型足够，动机是成本经济学（RouteLLM、Martian 等业界实践）。本项目双供应商配置（DeepSeek 主力 / Qwen 备选）已预埋管道，W7 成本周候选切入点：加"难度预判"即升级为级联。

一句话：通道路由决定"干什么"，大小模型路由决定"用谁干"，模型分类器只是通道路由的一种实现方式。
- 砍掉 RAG 通路、全走 Agent：丢失"检索为空不调用模型"的防幻觉闸门与结构化 sources。否决。
- 对话页直接改调 `/ai/agent`：回避而非解决不对称，且丢 RAG 闸门。否决。

## 后果

- 正：对话页单入口即全能力（实测：复合问题拿到工具级精度答案；纯知识问题仍多源引用 + 硬拒答）。
- 负/已知边界：①AGENT 通路 sources 恒空（引用在正文内）——结构化溯源对齐留待后续（需捕获工具调用记录）；②规则路由对"隐晦取数意图"（如无关键词的"去年赚多少"）会落入 RAG——接受此漏检率，W8 评估周用真实语料回顾；③检索对问法敏感的新发现（"12987 工艺"问法被拒答，"酿造工艺"问法正常）记入 W8 评估素材，非本次路由缺陷。
