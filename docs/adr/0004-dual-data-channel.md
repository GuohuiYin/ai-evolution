# ADR-0004：双数据通路架构 + mock 先行策略

- 状态：已接受
- 日期：2026-09-03（W4 通路辨析落地，2026-09-05 补记）

## 背景

个股研究需要两类数据：公告/研报等静态文本，与行情/财务等时变数字。两者进入系统的通路选择直接影响检索质量、数据新鲜度与成本。

## 决策

1. **通路一（RAG 向量库）**：静态、长文本、语义驱动——公告、研报、业务资料。摄入时向量化入 Qdrant，运行时语义检索。
2. **通路二（实时拉取）**：时变、结构化、精度敏感——行情、财务摘要。运行时经 `StockDataClient` 实时拉取，不进向量库（向量库语义检索对数字精度不友好，且行情有时效性，入库即腐坏）。
3. **判断标准**：数据随时间变化且要求精确 → 通路二；静态且需要语义匹配 → 通路一。
4. **mock 先行**：真源（Tushare/东方财富）接入前，以 `MockStockDataClient` 内置种子数据跑通全链路；`@ConditionalOnProperty(ai.stock.data-source)` 切换 mock/真源，链路代码零改动。

## 备选方案

- 全部进向量库：行情数字经 embedding 后语义检索精度不可靠，且需要持续同步。否决。
- 全部实时拉取：公告长文本无现成低延迟 API，且检索本质是语义问题。否决。

## 后果

- 正：每条数据走在适合它的通路上；真源接入被解耦为纯适配层工作（实现 `StockDataClient`）。
- 负：调用方需理解双通路分工（已由 `StockAnalysisService` / `RagChatService` / 工具层分别承载，A9 分包后边界清晰）。
- 待办：真源适配器（W 后续），接入时回归本 ADR 的判断标准。
