# ADR-0024：自建认证中心（Spring Authorization Server）vs Keycloak/云 IdP

- 日期：2026-11-07（W30 #4）
- 状态：已采纳
- 关联：ADR-0022（收口 Spring Security 链）、ADR-0023（直切资源服务器）、[W30 计划](../plans/advanced/w30-unified-auth-center.md)

## 背景

W30 立项时 Owner 裁决「学习目标优先」自建 IdP；#4 收口要求把 why/why-not 正式成文，
并登记密钥管理与令牌生命周期两项运维语义。

## 决策

1. **自建，但用框架不造协议**：认证中心 = Spring Authorization Server（SAS 已并入 Spring
   Boot 4 官方栈，BOM 托管）。授权码+PKCE（人）/ 客户端凭证（机）双通道，JWT RS256 签发 +
   JWKS 公钥端点。
2. **初始密钥管理**：签名密钥两通道——`AUTH_JWT_PRIVATE_KEY`（PKCS8 PEM）注入持久密钥
   （部署态经 Secret，A5）；缺省每启动临时生成 + WARN 有声化（本地开发姿态，重启换钥全失效、
   客户端重登录即恢复）。PEM 解析失败 fail-closed。**密钥轮转规程顺延 W31**（与韧性捆合并）。
3. **令牌生命周期语义**：访问令牌 TTL 1 小时（SAS 默认 5 分钟对对话体验太碎）。不发
   refresh token（SPA 过期即 401 → 自动重登，中心会话存活时秒回，等效无感续期）。
   **吊销语义 = 换钥**：无逐 token 吊销通道（无 introspection 端点），单 token 泄露窗口 =
   TTL 上限 1 小时；全员吊销 = 换签名密钥（重启发新钥）。单 Owner 本地实例接受此窗口；
   对外服务化时重评（缩短 TTL + introspection/吊销列表）。
4. **身份存储**：用户表 MySQL auth schema（argon2 哈希，明文不过夜）；admin 只能来自
   env 种子，注册（#6）永远产不出 admin。

## 备选与 why-not

- **Keycloak（自建开源 IdP）**：功能全（社会化登录/主题/管理台开箱即用），但——
  ① 本课程目标是亲手搭一遍 Java 生态的标准答案，黑盒接现成学不到协议内构；
  ② 单 Owner 单系统，Keycloak 的资源开销与运维面（独立 DB/主题定制/版本升级）远超收益；
  ③ 触发重评条件：多系统接同一身份源、需要社会化登录/SSO 联邦、或团队化运营。
- **云 IdP（Auth0/阿里云 IDaaS 等）**：免运维但把身份面交给厂商，与「可复现/可论证」
  红线相悖（他人无法低成本重现），且学习价值为零。触发重评条件：项目转对外产品。
- **继续共享 API Key**：无身份/角色/过期语义，泄露即全权限且无法吊销——W29/W30 的全部
  工作正是为了离开它。

## 后果

- 认证逻辑从业务系统彻底剥离：主工程不认证任何人，只验签（ADR-0023 已落地）。
- 本地开发每次重启 auth-center 换钥：对话页与脚本会 401 一次后自动恢复（重登/重取），
  可接受；想消除则注入持久密钥。
- 运维缺口显式在案：密钥轮转规程（W31）、逐 token 吊销（触发条件：对外服务化）。
