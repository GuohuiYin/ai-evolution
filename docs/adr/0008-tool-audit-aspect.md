# ADR-0008：工具调用审计用 AOP 切面（非埋点入侵）

- 状态：已接受
- 日期：2026-09-04（W5-Step2 落地，2026-09-05 补记）

## 背景

金融合规要求：模型自主触发的每一次数据访问（工具调用）必须可回放——参数、结果摘要、耗时、成败。需要裁决留痕的实现位置。

## 决策

**AOP 切面统一拦截**（`ToolAuditAspect`，`@Around("@annotation(Tool)")`）：

1. **切面无入侵**：工具方法体保持纯业务逻辑，审计关注点不渗入；新增工具自动获得审计能力（开闭原则）。
2. **雏形落 logger（`tool-audit`），生产可无缝切换**：当前写专用 logger；后续切审计表/ES 只改切面一处，工具零改动。
3. **计时用 `nanoTime()`**：审计耗时必须单调，不受系统时钟回拨影响。

## 备选方案

- 每个工具方法内手工埋点：重复代码 + 易遗漏 + 业务审计混杂。否决。
- Spring AI 的 ToolCallback 包装：可行但需自定义注册链路，且遮蔽 `@Tool` 注解的声明式风格。否决（W6 接 MCP 时重审）。

## 后果

- 正：审计覆盖率 = 工具覆盖率，由切点表达式保证，冒烟已实证留痕。
- 负：切面逻辑对新手不透明（由本 ADR 与类注释缓解）；异常路径只记 errorType，详细堆栈仍在应用日志，两日志需按 trace 关联（W7 观测性增强时处理）。
