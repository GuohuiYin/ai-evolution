# ADR-0001：从零搭建 ai_evolution 与技术栈选型

- 状态：已接受
- 日期：2026-09-02
- 决策者：Owner + AI 协作导师

## 背景

目标是在 13 周实战 + 14 周进阶内，从 Java 架构师转型为能独立交付
"带护栏、可评估、走协议"的 AI 应用架构师。需要一个贯穿全程的项目载体。

## 决策

1. **从零新建仓库**而不在既有项目上改造：
   - R1 干净的实验田——每个选型都是自己的决策，能在 README 讲出 why；
   - R2 没有历史包袱——专注 Agent 能力而非与遗留系统周旋；
   - R3 可求职的作品集——成品代码 + 架构图 + eval 报告三位一体。
2. **业务域选个股研究**：金融合规红线是 Harness 最好的教材；历史事实题天然
   适合建黄金测试集；研究循环（拉→算→查→验→出）天然是 Loop 素材。
   明确不做"涨跌预测"，只做"前瞻观点聚合 + 风险评估"。
3. **技术栈**（2026-09 时点，Maven Central 核实的最新稳定版）：
   - Java 25 LTS（本机 Oracle JDK 25.0.3）
   - Spring Boot 4.1.1（最新 GA；不采用 4.2.0-M1 里程碑版）
   - Spring AI 2.0.1 BOM（最新 GA；W1 后续步骤引入）
   - Maven 3.9.16（Wrapper 锁定，规避本机 JAVA_HOME 未配置问题）
   - 容器化：Spring Boot Buildpacks；本地编排：minikube v1.38.1
4. **模型接入**：DeepSeek / Qwen（OpenAI 兼容接口），W1 只搭骨架，
   真实接入待 Owner 提供 API Key 后进行，选型结论须有实测数据支撑。

## 后果

- 正：技术栈全部为当前稳定版，社区支持与文档最全；实验田无历史约束。
- 负：所有基础设施（CI、格式化、部署）需自行搭建，W1 工作量略增。
- 约束：Spring Boot 4.x 为较新大版本，遇到生态兼容问题时优先查官方迁移指南，
  并在 ADR 中追加记录。
