# ADR-0006：RAG 手动编排（弃用 Advisor 黑盒）+ 空检索硬拒答

- 状态：已接受
- 日期：2026-09-03（W3 落地，2026-09-05 补记）

## 背景

Spring AI 提供 `QuestionAnswerAdvisor` 一行接入 RAG。需要裁决：用框架黑盒还是手动编排检索→拼 prompt→调模型链路。

## 决策

**手动编排**（`RagChatService` 自持检索与拼 prompt），原因：

1. **引用来源必须随响应返回**（金融红线三）：Advisor 把检索结果吞进上下文后，响应里拿不到结构化 sources；手动编排让 `ChatAnswer(reply, sources)` 成为一等公民。
2. **空检索硬拒答**（防幻觉闸门）：检索为空时不调用模型直接拒答——这道闸门必须在"调模型之前"，Advisor 管道内无法表达该语义。
3. **可观测与可调**：检索参数（topK/阈值/未来的 rerank）在手写代码里可见可调，eval 能精确测量检索层质量（ADR-0007 的 Recall@K 依赖此）。

## 备选方案

- `QuestionAnswerAdvisor`：接入快，但上述三点全部无法满足。否决。
- 自定义 Advisor 扩展：可解决 1，但 2 的语义仍需管道外判断，复杂度不低于手动编排。否决。

## 后果

- 正：链路每一步可测可控，M1 验收门的 Recall@5 测量由此成为可能。
- 负：框架升级时需自行跟进 API 变化；代码量略增（可接受，核心逻辑不足百行）。
