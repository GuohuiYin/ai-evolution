## 背景（为什么做）

两条线同一个病灶——**多轮研究能力缺的零件**：

1. **ReAct 显式化**：当前 `AgentChatService` 的工具调用是隐式的（模型决定 → Spring AI 内部循环 → 终答），
   轨迹不可见、步数不可控、中途状态不可观测。研究 Loop 要求"提问→检索→综合→再提问"，
   必须先把循环拿到明面上——Harness「Correct」域的系统化起点
2. **查询改写**：W10 #0c 冒烟实锤——记忆 advisor 只解决了模型侧上下文，
   **检索拿原始追问去向量化**，指代未消解；它是多轮 RAG 的咽喉，也是 Loop 多步检索的前置

多轮能力必须有自己的评测集，否则改写与 Loop 效果无度量（A14 对账挂账项）。
