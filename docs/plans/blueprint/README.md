## 0. 总纲：一份蓝图的两种用法

| 组成 | 回答什么 | 用法 |

| 知识深度地图（L0-L4 清单 + 三档深度） | 每个技术点学到什么深度 | 每周对照作战地图时查它，确认深度目标 |

节奏：周一定要点 → 周内动手（断点按降级原则）→ 周末 15 分钟周记 → 里程碑验收门。

**四条铁律**：

1. 动手 > 阅读（唯一硬约束）；读不完进泛读清单下季度补
2. 没有产出物的学习只是阅读清单——13 周末是 5 件交付物，不是"学完了"
3. 禁止跳层：L1-L3 未达标不进 L4
4. 所有数字标注口径：阈值均为经验基线，能回溯出处或实测验证才可引用

**深度三档**：会用（跑通示例+说清何时不该用）/ 会调（生产调优+量化记录+定位故障）/ 会造（读源码+画内部结构图+30 分钟分享）。

## 1. 定位与原则

- **为什么从零建 ai_evolution**：干净实验田（每个选型都是自己的决策）、无历史包袱、可求职的作品集三位一体（成品代码+架构图+eval 报告）
- **统一业务域**：个股研究（订单/商品/库存/持仓快照/自选池为统一素材），13 周都要回头查它
- **时间盒**：13 周实战（每周 8-10h）+ 14 周进阶（每周 6-8h）；时间盒是防拖延工具，验收门没过就停下来补齐
- **核心纠偏——不预测**：不让模型猜涨跌；做前瞻观点聚合 + 风险评估（一致预期/催化剂/多空逻辑/风险情景的结构化视图）

**失败归因对照表**（L0 能力边界认知的实战应用）：

| 误判 | 归因 | 正确动作 |
|---|---|---|
| 答错历史事实 | L2 检索缺失 / 数据未入库 | 查摄取管线与召回，不是调 Prompt |
| 编造数字 | L3 缺"数字可溯源"约束 | Harness 强制来源+时点注入 |
| 给了买卖建议 | L3 缺合规护栏 | 拒答策略 + 引导回结构化对照 |

**金融三条设计红线**（写进 Harness 全项目生效）：① 免责声明强制附带 ② 禁止具体买卖建议 ③ 数字必须可溯源（数据源+时点必带）。

**金融域四份红利**：历史事实题天然好建黄金集；公告/研报天然混入指令式语言（注入素材）；金融合规是最好的 Harness 教材；研究循环天然是 Loop。

## 2. 路径总览：L0→L4 × 27 周

横切层贯穿全程：可观测性 · 成本工程 · 安全与合规。

| 层 | 周 | 主题 | 实战交付 |
|---|---|---|---|
| L0 模型认知底座 | W1（进阶期回补深化） | 读懂模型 | 模型选型笔记 |
| L1 Prompt 工程 | W2 | 单次交互质量 | P0 个股分析 + Prompt 版本化 |
| L2 Context 工程 | W3-4 | 看什么信息 | P1 RAG（Recall@5≥0.7） |
| L3 Harness 工程 | W5-9 | 怎么安全跑 | P2 MCP Server + 护栏 + Eval |
| L4 Loop 工程 | W10-13 | 怎么自己转 | P3 最小研究 Loop + 护栏 |
| 进阶期 | W14-27 | 捡回砍掉的范围 | 见 §6 |

**依赖逻辑（跳步必返工）**：L0 边界认知是 L1 退出判断前置；LLM-as-a-Judge 是 L2/L4 所有评估前置；基础 RAG 调优是 GraphRAG 前置；评估集构造是验收前置；权限审计是多 Agent 前置。

**八项存量能力迁移**（Java 架构师不平移到零）：熔断限流→Correct 机制（低）、微服务治理→MCP 权限管控（低）、MQ 事件驱动→L4 触发（低）、工作流引擎→Loop 编排（中，非确定性冲击）、Micrometer→Token 计量（低）、CI/CD→Eval Pipeline（低）、Redis 分层缓存→记忆分层/语义缓存（中，近似命中≠精确命中）、JVM 调优→Token 成本工程（低）。主攻"真正新"的：评估体系、Prompt 方法论、检索质量调优、非确定性系统架构设计。

## 4. 横切层（W7 集中落地 + 层层同步）

- **可观测性**：Micrometer 调用链（会调，W8）、OpenTelemetry GenAI 语义（会用）、分层故障特征清单（会造：L1 格式漂移/L2 召回缺失/L3 越权死循环/L4 空转预算失控）
- **成本工程**：Token 计量（W1 手算起步，W8 一页成本账）、模型路由强弱分流（会调）、prompt caching/语义缓存（W7）、成本仪表盘与预算告警（进阶期，会造）
- **安全与合规**：Prompt Injection 防护（W7 实验）、工具权限逃逸（最小权限）、MCP 供应链风险（会用，纳入选型审查）、金融合规法规出处跟踪、红队测试（安全性目标 100%，无灰度空间）

## 7. 机制

- **每周例行**：周日晚 45 min 扫信息源记 1-3 条业界变化；每月末 30 min 更新认知地图；每周末 15 min 周记
- **信息源清单（只盯这些）**：一手 Anthropic/OpenAI blog、MCP spec、Fowler、Osmani；生态 Spring AI / LangChain4j release notes；二手 Latent Space、Simon Willison；金融合规法规跟踪。精读 10-15 篇 + 泛读 1-2 篇/周
- **降级原则（防烂尾）**：落后 ≤3 天挤占 W9 缓冲周；1 周砍 Temporal；2 周砍 minikube 部署；严重落后删 P3 保 P0+P1+P2+Eval 底线

## 8. 边界（27 周后在哪里）

**得到**：独立交付带护栏、可评估、走协议的 Java Agent 系统；讲清 L0-L4 与每层退出标准；黄金集 eval 持续观测；MCP Server 被真实客户端调用；ReAct Loop 串研究流程；一次"框架+实测"分享。
**还不是**：多 Agent 生产级实战、无人值守组织级信任、build/buy 实战、C 端高并发可观测——放进再下个 6-12 个月。
