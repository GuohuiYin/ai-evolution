## 1. Sub-Agent 协作：三角色选型与职责切分

### 1.1 现状痛点（为什么拆）

当前 ResearchLoop 是**单体循环**：一个 system prompt 身兼问题拆解、取证执行、
措辞综合、自查自纠四职。W18-W20 的 eval 病灶多半长在职责混杂处——

- 触顶合成（MAX_STEPS）是"执行者给自己批卷子"，W19 泄漏假象、W20 中期分红
  张冠李戴都发生在综合环节无人复核；
- 红线切面（RedLineAuditAspect）是关键字层防线，语义层的"该拒不拒/口径串台"
  只能靠 eval 事后发现（W20 #1 串台案 judge 与人工双双漏抓过）；
- 计划与执行耦合：模型边想边查，多跳问题（compound 类）的子问题覆盖全凭当场发挥，
  eval 显示 compound 类长期是最低分类别（4.6/6，W21 批）。

### 1.2 选型：Planner + Builder + Reviewer，舍 Monitor

蓝图四角色取三，取舍依据是本域的一等约束：

| 角色 | 取舍 | 理由 |
|---|---|---|
| **Planner** | ✅ | compound 类是最弱项——多跳问题需要显式计划先行，把"边想边查"改成"先列子问题再取证" |
| **Builder** | ✅ | 现 ResearchLoop 的执行面（ReAct 取证循环）原样继承，职责收窄为"按计划取证 + 起草" |
| **Reviewer** | ✅ | 金融域红线/溯源是一等公民，需要**独立于作者**的语义复核——在线版的"裁判不进赛场"（与 eval judge 的 ADR-0014 隔离哲学同构） |
| **Monitor** | ❌ 舍 | 预算/熔断/告警职责与 Temporal 事件历史（ADR-0019 执行语义面）及 W24-27 成本工程周重叠；届时以平台能力回补，不造重复轮子 |

### 1.3 三角色边界表（Owner 过目核心）

| | Planner | Builder | Reviewer |
|---|---|---|---|
| **输入** | 用户问题 + 会话窗口历史 | 研究计划 + 会话历史 | 草稿 + 证据包 + 红线约束 |
| **输出** | 研究计划（子问题序列，每个标注取证通路：RAG / 行情工具 / 公告工具） | 证据包（检索/工具原始结果+出处）+ 草稿终答 |  verdict：通过 / 打回（带批注） |
| **工具权限** | **无**（纯规划，不碰数据） | 全部取证工具（经 ToolRegistry 白名单，现状不变） | **只读证据包，无工具**（防复核者自己下场改证据） |
| **红线责任** | 无 | 措辞层面遵守（现 system prompt 约束继承） | 兜底裁决：买卖建议/编造/溯源缺失一律打回 |
| **失败语义** | 计划不可解析 → 降级为单子问题"直接回答原问题"（不阻塞链路） | 触顶/工具故障 → 现状语义（answer=null 不编造） | 打回 ≤2 次仍不过 → 出拒答文案（宁可不答不可错答） |
| **模型档位** | 轻量档（规划是结构化任务） | 主力档（现状模型） | 主力档（复核质量不能省） |

### 1.4 编排与既有资产的关系

- **承载**：串行管线 `Planner → Builder → Reviewer →（打回 ≤2 次）→ 终答`，天然落在
  Temporal workflow 上（W21 #1② 已铺轨：每角色 = 一个 activity，事件历史白得每角色
  的输入/输出/耗时/重试留痕）；inline 引擎保留单循环现状作对照臂。
- **消息契约**：`Plan`（子问题+通路标注）/ `EvidencePack`（证据+出处列表）/
  `DraftAnswer` / `ReviewVerdict`（通过 | 打回批注）——四个不可变记录，跨 activity
  边界压平（HistoryTurn 同款先例）。
- **与 eval judge 的边界**：Reviewer 是在线组件（拦在回答出炉前），judge 是离线评估
  （ADR-0014 隔离不变）；两者 rubric 同源不同身——Reviewer 的复核清单复用 rubric
  三维语义但**不共用 prompt 文件**，防"改评估尺误伤在线行为"的耦合。
- **与红线切面的边界**：切面=关键字层（快、硬、可审计），Reviewer=语义层（口径串台、
  该拒不拒）；两层互补，切面不动。
- **HITL 钩子**（W22-23）：Reviewer 通过后、终答发出前是天然的审批断点位——
  Temporal Signal 挂起等人工放行，本设计预埋不断点实现。

### 1.5 被否方案

- **四角色全上（含 Monitor）**：成本/熔断在 Temporal + W24-27 成本周已有落点，重复。
- **Reviewer 合并进 Builder 自查**：W19/W20 已实证"作者自查"会漏（泄漏假象、张冠李戴
  均为自查盲区）；独立性是 Reviewer 的全部价值。
- **并行多 Builder 抢答**：串行已够，并行引入证据合并难题；eval 无证据表明并行必要。

## 2. Skill 渐进披露：调研与 Token 降幅测量方案（W22 实测铺路）

### 2.1 概念（蓝图 4.4）

Skill = 「指令 + 资源」的可复用包（分析规程、工具手册、写作范式），渐进披露三层：

1. **元数据层**：name + 一句话 description（约数十 token），常驻上下文；
2. **正文层**：命中触发条件后加载 SKILL.md 全文（数百至数千 token）；
3. **资源层**：附属文件/脚本按需再加载。

对照现状：本项目 prompts/ 是**静态全量注入**——system prompt 不管问题用不用得上，
每次都全文进上下文。个股研究域的技能库一旦长大（分红口径规程、年报横读规程、
行业对比范式……），全量注入的 token 成本线性膨胀。

### 2.2 技能化候选盘点（本域）

| 候选 skill | 触发条件 | 现状位置 |
|---|---|---|
| 分红口径分析规程（中期/年度/合计口径） | 问题含"分红/派息" | 散落在 golden 参照与 prompt 示例（W19-W20 病灶高发区） |
| 年报横读规程（主要会计数据→合并报表互验） | 问题含"营收/净利+同比" | agent-react-v2 内嵌指令 |
| 拒答边界规程（在库/不在库判定） | 期望行为 refuse-nodata 类 | 同上 |
| 工具使用手册（三工具参数细节） | Builder 取证时 | agent-react-v2 内嵌 |

### 2.3 渐进披露设计（W22 实现面）

- `SkillRegistry`：`skill/` 目录扫 SKILL.md（YAML front-matter：name/description/
  triggers），元数据层注入 system prompt（每个 skill 一行）；
- 命中触发（关键词/Planner 标注通路）→ 该 skill 正文注入当轮；
- 与三角色正交：Planner 的计划输出可直接标注"本子问题需 skill X"，触发从关键词
  猜测升级为计划显式声明——三角色与 Skill 两个 W21-23 主题在此交汇。

### 2.4 Token 降幅测量方案（W22 实测执行本方案）

**双臂对照，同案同种子**：

| 臂 | 注入策略 |
|---|---|
| A（基线臂） | 全量注入所有 skill 正文（= 现状语义下把候选 skill 内容全部塞进 system prompt） |
| B（渐进披露臂） | 仅元数据常驻 + 命中触发注入正文 |

**测量口径**：

1. **数据集**：57 案生成 eval 批原样复用（已含各类别分布），每案跑两臂；
2. **Token 采集**：DeepSeek API 返回的 `usage.prompt_tokens` 逐案记录（真账，
   不依赖本地 tokenizer 估算）；按"触发 skill / 未触发"分组统计；
3. **指标**：平均 prompt_tokens/案、P50/P95、按 57 案折算单批成本差；
4. **质量守线**：B 臂 judge 总分相对 A 臂的跌落须在运行间抖动带内（参照 W21
   实测：同栈双批逐案 churn ~25/57、总分差 0.2 以内）——**降 token 不许掉质量**；
5. **守线建议（Owner 过目）**：B 臂平均 prompt token 降幅 **≥40%** 判定渐进披露
   "值得"；降幅 <20% 说明技能库太小、机制本身不划算，登记认知后止步（不硬上）。

**误判防线**：触发误判（该加载没加载）会直接掉质量——B 臂逐案记录"触发了哪些
skill"，凡质量分差超 ±1 的案先查触发日志再判机制优劣，防"机制背触发的锅"。

## 3. 落地顺序建议（W22-23 铺排输入）

1. W22 上半周：三角色管线（Temporal activity 化）+ 离线 eval 对照（57 案双臂）；
2. W22 下半周：SkillRegistry + 本方案实测（Token 降幅报告）；
3. W23：HITL 审批断点（Reviewer 后 Signal 挂起）+ L4 全项验收。

## 4. 风险与开放问题

- Reviewer 打回循环的 token 成本：每打回一次 = Builder 重跑一轮，eval 预算需计入；
- Planner 轻量档模型选型未实测（W22 第一周事）；
- Skill 触发的误触发率无先验——测量方案 §2.4 误判防线即为此设；
- 三角色后 ResearchLoop 单体循环是否退役：建议双轨并行至少一周（inline 单循环 vs
  temporal 三角色对照），数据说话后再裁。
