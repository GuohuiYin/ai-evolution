# 里程碑规划手册（Planning Playbook）

> 2026-09-11 立。把历次里程碑规划（M2→M3）的隐式流程显式化——新会话凭本手册 + 仓库现状即可完整制定下一阶段计划，不依赖特定会话的记忆。
> 触发时机：里程碑验收门通过时（或 Owner 指令）。

## 输入清单（规划前必须齐备）

| 输入 | 位置 | 用途 |
|---|---|---|
| 课程蓝图 | [blueprint/README.md](blueprint/README.md)（蒸馏自完整版 PPT） | 北极星：整体目标、深度坐标、进阶期归期 |
| 当前里程碑验收记录 | `mX/mX-acceptance.md` | 证据池：哪些达标、哪些擦线、哪些欠账 |
| 能力地图 | `docs/capability-map.md` | 差距台账 + 挂账候选池（W14+ 清单） |
| 近期周记 | `docs/journal/` | 失败案例与教训（证据驱动排序的素材） |
| AGENTS.md | 仓库根 | 规划过程必须遵守的规范（A14/A15 等） |

## 五步流程

1. **蓝图对账**：对照 blueprint 中本阶段原定范围，标出超前项 / 遗漏项 / 降级项，每项注明去向（先例：`docs/plans/README.md` 的"对账校准记录"）
2. **A14 能力域对账**：对照生产级 Agent 能力域清单（上下文构建/管理/优化、多轮会话、记忆、规划、工具、评估、安全、可观测、交互形态、韧性）逐项反推"我有吗？没有是有意取舍还是盲区？"——**没有证据 ≠ 没有问题，监控盲区即规划盲区**
3. **A15 差距扫描**：双参照系成对使用——横向切面（安全/交互/可复现/韧性/成本）+ 纵向管线解剖（RAG 管线与 Agent Loop 逐阶段过）+ 能力地图逐项对照；新发现的差距补入 capability-map
4. **证据驱动排序**：候选项按"失败案例证据强度 × 依赖先后"排序；每项给出：定位（骨架/增强/攻坚）、证据/依据、建议周次；无证据支撑的项降级为挂账观察
5. **成文与裁决**：产出阶段索引页（`mX/README.md`：候选裁决表 + 周索引 + 挂账清单 + 验收门草案）+ 逐周计划文档；**提交 Owner 裁决后生效**——规划是提案，不是决定

## 周计划文档模板（`mX/wN-<slug>.md`）

固定段落，缺一不可：

1. **背景（为什么做）**：现状痛点 + 证据引用
2. **任务分解表**：`# | 任务 | 验收条件 | 状态`——状态列随执行更新（✅ + commit hash / ⬜），进度标记长在文档自己身上
3. **明确不做（防范围蔓延）**：列出相邻但本周不碰的事及其归期
4. **顺序与节奏**：任务先后依赖；每天 1 项以内，TDD 先红后绿，逐项 review
5. **退出条件**：本周收工的判定标准（O8）

## 规划纪律

- 详细周计划只排到当前里程碑末周；更远期以挂账清单形态存在——提前细排的贬值速度很快（reranking 从 M3 首轮规划漏网即前车之鉴）
- 每个候选必须能讲出 why 与 why-not（质量标准第 2 条：可论证）
- 验收门草案随首周开工定稿，每条必须是"有可跑的命令或可看的证据"
- 蓝图与执行冲突时以周计划为准，但偏差必须在周记留痕；蓝图本身的修订走 PPT → 蒸馏同步流程（见 blueprint/README.md 头部）
